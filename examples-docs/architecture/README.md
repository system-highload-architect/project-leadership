## 1. Введение

Данный раздел содержит **все архитектурные артефакты** E‑Commerce платформы: решения (ADR), API-контракты, модель данных и диаграммы. Все документы связаны между собой и отражают эволюцию архитектуры от модульного монолита к распределённой системе.

**Цель:** Обеспечить единое понимание архитектуры для всех участников проекта — от бизнес-аналитиков до разработчиков и DevOps-инженеров.

## 3. Принципы построения диаграмм

Все диаграммы в этом разделе строятся по следующим принципам:

1. **Текстовый формат (PlantUML).** Все диаграммы хранятся в виде `.puml` файлов для версионирования и автоматической генерации SVG.
2. **Многоуровневость.** Для каждого архитектурного паттерна мы создаём отдельные наборы диаграмм:
   - **Модульный монолит** — диаграммы для текущей архитектуры.
   - **Микросервисы** — диаграммы для целевой архитектуры (при переходе).
   - **EDA** — диаграммы, показывающие событийные потоки.
   - **Serverless** — диаграммы для гипотетического бессерверного варианта.
3. **Связь с ADR.** Каждая диаграмма ссылается на соответствующие ADR, обосновывающие выбор архитектуры.
4. **Интеграция с документацией.** Сгенерированные SVG встраиваются в Markdown-документы для удобного просмотра.

## 4. Типы диаграмм

### 4.1 C4-диаграммы (для каждого паттерна)

- **Context** — система и её взаимодействие с внешним миром (пользователи, внешние системы).
- **Containers** — высокоуровневые технологические блоки (веб-приложения, API, БД, брокеры).
- **Components** — внутреннее устройство одного контейнера (например, Order Service).
- **Dynamic** — динамика взаимодействия (потоки данных при выполнении сценариев).
- **Deployment** — развёртывание на инфраструктуре (Kubernetes, облако).
- **Code** — детали реализации (классы, интерфейсы, структуры данных) — для Go.

### 4.2 ER-диаграммы (для каждого паттерна)

- **Conceptual** — бизнес-сущности и их связи (без атрибутов).
- **Logical** — атрибуты, первичные и внешние ключи, типы данных.
- **Physical** — конкретная схема PostgreSQL с индексами, ограничениями, каскадными действиями.

### 4.3 UML-диаграммы (для каждого паттерна)

- **Структурные:** классы, объекты, компоненты, развёртывание, пакеты, композитная структура, профили.
- **Поведенческие:** варианты использования, деятельность, состояния, последовательности, коммуникации, временные, обзора взаимодействия.

```
diagrams/

│   ├── c4/
```

## 7. Как использовать диаграммы

1. **Для знакомства с проектом** — начните с C4 Context и Containers (для текущего паттерна — монолит).
2. **Для понимания структуры данных** — изучите ER-диаграммы.
3. **Для детального проектирования** — используйте UML-диаграммы и C4 Components/Code.
4. **Для планирования эволюции** — посмотрите диаграммы для микросервисов и EDA.

## 8. Генерация диаграмм

Для генерации SVG из `.puml` файлов используйте команду:

```bash
make generate-diagrams
```

Или вручную:

```bash
plantuml -tsvg diagrams/**/*.puml
```

Сгенерированные SVG встраиваются в Markdown-документы через `![диаграмма](path/to/diagram.svg)`.
