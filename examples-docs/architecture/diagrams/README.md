# Диаграммы архитектуры: E‑Commerce Platform

**Версия:** 1.0  
**Дата:** 2026-07-26  
**Статус:** Черновик

---

## 1. Введение

Этот раздел содержит **все визуальные представления архитектуры** E‑Commerce платформы. Диаграммы — это ключевой инструмент для понимания структуры системы, потоков данных, взаимодействий и эволюции архитектуры.

Все диаграммы построены с использованием **PlantUML** и хранятся в виде текстовых `.puml` файлов, что позволяет версионировать изменения и автоматически генерировать SVG для встраивания в документацию.

---

## 2. Почему диаграммы разделены по паттернам

Система E‑Commerce спроектирована так, чтобы **эволюционировать** от простого модульного монолита к более сложным архитектурным стилям по мере роста нагрузки, команды и требований. Мы отражаем эту эволюцию в диаграммах, создавая отдельные наборы для каждого ключевого паттерна:

| Паттерн | Описание | Когда актуален |
|---------|----------|----------------|
| **Модульный монолит** | Текущая архитектура на старте проекта | Этап 1 (MVP) |
| **Микросервисы** | Целевая распределённая архитектура | Этап 3–4 (при росте) |
| **EDA (Event-Driven)** | Событийно-ориентированная архитектура (с Kafka) | Все этапы (ядро системы) |
| **Serverless** | Бессерверный вариант для отдельных функций | Гипотетический вариант |

Каждый набор диаграмм показывает, как система выглядит и взаимодействует в рамках соответствующего стиля.

## 4. Типы диаграмм

### 4.1 C4-диаграммы (для каждого паттерна)

| Уровень | Назначение | Пример |
|---------|------------|--------|
| **Context** | Показывает систему в окружении (пользователи, внешние системы) | «Покупатель → E‑Commerce → Платёжный шлюз» |
| **Containers** | Высокоуровневые технологические блоки | Web UI, API Gateway, Order Service, PostgreSQL, Kafka |
| **Components** | Внутреннее устройство контейнера (например, Order Service) | Контроллер, Use Cases, Domain, Репозитории, Адаптеры |
| **Dynamic** | Взаимодействие между контейнерами/компонентами при выполнении сценария | «Создание заказа: клиент → API → Order → Payment → Inventory → Notification» |
| **Deployment** | Развёртывание на инфраструктуре (Kubernetes, облако) | Pod'ы, Service'ы, Ingress, Persistent Volumes |
| **Code** | Детали реализации (классы, интерфейсы, структуры данных) для Go | `Order struct`, `OrderRepository interface`, `CreateOrderUseCase` |

### 4.2 ER-диаграммы (для каждого паттерна)

| Уровень | Назначение |
|---------|------------|
| **Conceptual** | Бизнес-сущности и их связи (без атрибутов) |
| **Logical** | Атрибуты, первичные и внешние ключи, типы данных |
| **Physical** | Конкретная схема PostgreSQL с индексами, ограничениями, каскадными действиями |

### 4.3 UML-диаграммы (для каждого паттерна)

| Категория | Типы диаграмм |
|-----------|---------------|
| **Структурные** | Классов, объектов, компонентов, развёртывания, пакетов, композитной структуры, профилей |
| **Поведенческие** | Вариантов использования, деятельности, состояний, последовательности, коммуникации, временные, обзора взаимодействия |

## 5. Принципы построения диаграмм

1. **Единый инструмент — PlantUML.** Все диаграммы описываются текстом в `.puml` файлах.
2. **Версионирование.** Изменения диаграмм фиксируются в Git вместе с кодом.
3. **Автоматическая генерация.** SVG генерируются из `.puml` через `make generate-diagrams`.
4. **Связь с ADR.** Каждая диаграмма должна ссылаться на соответствующие ADR.
5. **Синхронизация с кодом.** Диаграммы обновляются при изменении архитектуры или модели данных.

## 6. Как использовать диаграммы

### Для разработчиков
- Начните с **C4 Context и Containers**, чтобы понять общую структуру.
- Перейдите к **UML-диаграммам классов** для деталей реализации.
- Используйте **ER-диаграммы** для понимания модели данных.

### Для архитекторов
- Используйте **C4 Components** и **Dynamic** для анализа взаимодействий.
- Сравнивайте **диаграммы для разных паттернов**, чтобы планировать эволюцию системы.

### Для DevOps
- Используйте **C4 Deployment** для планирования инфраструктуры.
- Используйте **UML-диаграммы развёртывания** для детализации Kubernetes-ресурсов.

### Для новых членов команды
- Начните с **C4 Context**, затем Containers, Components.
- Затем изучите **UML-диаграммы вариантов использования** для понимания функциональности.

## 8. Генерация диаграмм

Для генерации SVG из всех `.puml` файлов используйте команду:

```bash
make generate-diagrams
```

Или вручную:

```bash
plantuml -tsvg diagrams/**/*.puml
```

Сгенерированные SVG можно встраивать в Markdown:

```markdown
![Контекстная диаграмма](monolith/c4/context.svg)
```
