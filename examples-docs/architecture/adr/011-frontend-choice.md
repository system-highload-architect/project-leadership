# ADR-011: Выбор фронтенд-фреймворка

**Статус:** Принято  
**Дата:** 2026-07-26  
**Автор:** Tech Lead / Архитектор

---

## Контекст

Для E‑Commerce платформы необходим пользовательский интерфейс (Web UI) для:
- **Покупателей** — просмотр каталога, корзина, оформление заказа, история заказов.
- **Менеджеров** — управление товарами, заказами, клиентами.
- **Администраторов** — мониторинг, отчёты, настройки.
- **Поддержки** — просмотр заказов, помощь клиентам.

Требования к фронтенду:
- Высокая производительность (быстрая загрузка, отзывчивость, SEO-оптимизация).
- Современный стек (TypeScript, компонентный подход).
- Богатая экосистема (UI-компоненты, инструменты, документация).
- Простота разработки и поддержки командой.
- Возможность интеграции с REST и gRPC API.
- Поддержка сложных пользовательских сценариев (корзина, фильтры, пагинация, анимации).

Рассматривались:
1. **React** + TypeScript
2. **Vue 3** + TypeScript
3. **Svelte** / SvelteKit
4. **Angular**

---

## Решение

Выбран **React** (с TypeScript) в сочетании с **Vite** как сборщиком и **Ant Design** (или Material-UI) как библиотекой компонентов.

**Обоснование:**

- **Экосистема:** React — самый популярный фреймворк, огромное количество готовых решений (UI-библиотеки, хуки, инструменты, интеграции).
- **TypeScript:** Строгая типизация снижает количество ошибок, улучшает поддержку кода.
- **Компонентный подход:** Позволяет переиспользовать UI-блоки, ускоряет разработку.
- **Производительность:** React + Vite дают быструю сборку и горячую перезагрузку (HMR).
- **Гибкость:** React не навязывает архитектуру, можно использовать только нужные инструменты (Redux, React Query, Zustand).
- **Интеграция с бэкендом:** Легко работать с REST API (fetch/axios) и gRPC-Web (если потребуется).
- **SEO:** Поддержка Server-Side Rendering (SSR) через Next.js для улучшения SEO (позже).
- **Поддержка сложных сценариев:** React хорошо справляется с динамическими интерфейсами (корзина, фильтры, анимации).

## Альтернативы

| Фреймворк | Плюсы | Минусы | Почему не выбран |
|-----------|-------|--------|------------------|
| **Vue 3** | Более простой синтаксис, отличная документация | Меньше вакансий и библиотек, чем React | Команда больше знает React |
| **Svelte** | Нет виртуального DOM, очень быстрый | Меньше экосистема, сложнее с интеграцией | Недостаточно зрелый для корпоративного проекта |
| **Angular** | Всё включено (маршрутизация, HTTP, формы) | Сложный, тяжёлый, крутая кривая обучения | Избыточен для E‑Commerce, сложнее поддерживать |

## Последствия

### Положительные
- ✅ Быстрая разработка благодаря готовым UI-компонентам.
- ✅ Лёгкий поиск разработчиков (React — самый популярный стек).
- ✅ Отличная интеграция с TypeScript.
- ✅ Возможность использовать React Query для управления состоянием серверных данных.
- ✅ Гибкость для будущих изменений (можно легко мигрировать на Next.js для SSR).
- ✅ Поддержка сложных пользовательских сценариев (корзина, фильтры, анимации).

### Отрицательные
- ❌ React сам по себе не даёт архитектуры — нужно выбирать дополнительные инструменты (стейт-менеджмент, маршрутизация).
- ❌ Может быть избыточен для простых страниц (но для E‑Commerce это не проблема).

### Компромиссы
- Используем **React Query** для кэширования и синхронизации с сервером.
- Для стейт-менеджмента используем **Zustand** (лёгкий, минималистичный).
- UI-библиотеку выбираем **Ant Design** (для админок и компонентов) с кастомизацией через TailwindCSS.
- Для SEO-оптимизации на старте используем **Next.js** (SSR для ключевых страниц: каталог, товар, корзина, оформление заказа).

## Связь с паттернами и будущими решениями

| Паттерн / Решение | Как связано с фронтендом |
|-------------------|--------------------------|
| **API Gateway** | Фронтенд общается с API Gateway (REST) |
| **CQRS** | Запросы (Query) — REST (получение данных). Команды (Command) — REST или gRPC-Web (изменение состояния) |
| **EDA** | WebSocket или Server-Sent Events (SSE) для получения событий в реальном времени (например, статус заказа) |
| **Saga** | Фронтенд инициирует команду (создание заказа) через REST, которая запускает Saga на бэкенде |
| **Абстрактные инструкции** | Фронтенд может отправлять сложные инструкции в теле запроса (JSON) для гибкой бизнес-логики |
| **SEO** | Next.js (SSR) для улучшения SEO и производительности |
