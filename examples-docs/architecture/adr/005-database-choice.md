# ADR-005: Выбор базы данных

**Статус:** Принято  
**Дата:** 2026-07-26  
**Автор:** Tech Lead / Архитектор

---

## Контекст

Для E‑Commerce платформы необходимо выбрать основное хранилище данных. Требования:

- **ACID-транзакции** — целостность заказов, платежей, резервирования товаров.
- **Сложные запросы** — отчёты, аналитика, JOIN между таблицами (заказы + товары + пользователи).
- **Гибкость** — хранение полуструктурированных данных (метаданные товаров, корзина, история заказов).
- **Масштабируемость** — рост нагрузки, репликация, бэкапы, подготовка к шардированию.
- **Поддержка CDC (Change Data Capture)** — для интеграции с Kafka и событийной архитектурой.
- **Опыт команды** — разработчики знакомы с реляционными БД.

Рассматривались:

1. **PostgreSQL** — реляционная, с поддержкой JSON.
2. **MySQL** — классическая реляционная.
3. **MongoDB** — документо-ориентированная NoSQL.
4. **CockroachDB** — NewSQL, горизонтально масштабируемая.

---

## Решение

Выбрана **PostgreSQL** (версия 15+) как основная база данных.

**Обоснование:**

- **ACID-транзакции:** Гарантируют целостность данных при операциях с заказами, платежами и резервированием.
- **JSONB:** Позволяет хранить гибкие метаданные (например, атрибуты товаров, корзину, историю изменений) без потери производительности.
- **Индексы:** B-tree, GIN для JSONB, полнотекстовый поиск — всё необходимое для E‑Commerce.
- **Репликация:** Streaming Replication, Point-in-Time Recovery (PITR) — надёжность и отказоустойчивость.
- **CDC:** Интеграция с Debezium для публикации изменений в Kafka — естественная связь с EDA.
- **Экосистема:** Большое сообщество, инструменты миграции (`golang-migrate`), расширения (PostGIS, TimescaleDB, pg_cron).
- **Партиционирование:** Встроенная поддержка партиционирования (по диапазону, по списку, по хешу) — подготовка к росту данных.

## Альтернативы

| Альтернатива | Плюсы | Минусы | Почему не выбрана |
|--------------|-------|--------|-------------------|
| **MySQL** | Привычность, высокая скорость чтения | Слабее в JSON, партиционировании, сложных запросах | Недостаточная гибкость для метаданных и аналитики |
| **MongoDB** | Гибкая схема, горизонтальное масштабирование | Нет полноценных ACID-транзакций, сложные JOIN-запросы требуют агрегаций | Риск целостности данных при критических операциях |
| **CockroachDB** | Горизонтальное масштабирование, совместимость с PostgreSQL | Операционная сложность, меньше инструментов, выше стоимость | Избыточна для старта, можем перейти позже при необходимости географического распределения |

---

## Последствия

### Положительные
- ✅ Надёжность и целостность данных.
- ✅ Гибкость через JSONB.
- ✅ Простота миграций и бэкапов.
- ✅ Лёгкая интеграция с EDA через Debezium.
- ✅ Подготовка к шардированию через партиционирование.
- ✅ Возможность перехода на CockroachDB в будущем (совместимость протокола).

### Отрицательные
- ❌ Вертикальное масштабирование — один мастер, ограниченный ресурсами.
- ❌ Требуется грамотное проектирование индексов и партиционирования при росте.

### Компромиссы
- Внедряем **кэширование (Redis)** для разгрузки БД (сессии, корзина, частые запросы).
- Используем **репликацию** для отказоустойчивости и чтения (read replicas для аналитики).
- Планируем **партиционирование** по `created_at` для таблиц заказов и событий.

## Связь с паттернами и будущими решениями

| Паттерн / Решение | Как связано с выбором БД |
|-------------------|--------------------------|
| **CQRS** | Write DB — PostgreSQL (нормализованная схема). Read DB — PostgreSQL (денормализованные проекции) или ClickHouse для аналитики. |
| **Event Sourcing** | PostgreSQL используется как Event Store (таблица событий с JSONB). |
| **Saga** | PostgreSQL хранит состояние саги (координатор) или события компенсации. |
| **EDA** | Debezium (CDC) публикует изменения из PostgreSQL в Kafka. |
| **Шардирование (ADR-?)** | PostgreSQL поддерживает партиционирование и готов к переходу на Citus (распределённый PostgreSQL). |
| **Масштабирование** | При росте нагрузки добавляем read replicas, затем партиционируем, затем — Citus или CockroachDB. |
