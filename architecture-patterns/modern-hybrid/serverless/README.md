# Serverless (FaaS)

**Serverless** (или Function-as-a-Service, FaaS) — это модель развертывания, при которой код выполняется в ответ на события, а инфраструктура полностью управляется облачным провайдером. Разработчик пишет функции, а провайдер берёт на себя масштабирование, управление серверами и оплату только за фактическое время выполнения.

---

## 🧠 Основные принципы

1. **Нет управления серверами.**  
   Инфраструктура полностью абстрагирована.

2. **Оплата за выполнение.**  
   Вы платите только за время выполнения функции (миллисекунды × количество вызовов).

3. **Автоматическое масштабирование.**  
   Функции масштабируются автоматически под нагрузку.

4. **Событийная модель.**  
   Функции запускаются по событиям (HTTP-запросы, сообщения в очереди, изменение в БД, загрузка файла).

---

## 🧩 Когда использовать Serverless

- **Обработка событий** — загрузка файлов, уведомления, триггеры от БД.
- **Редкие и нерегулярные задачи** — резервное копирование, аналитика, генерация отчётов.
- **Быстрая проверка идей** — PoC, MVP, эксперименты.
- **Нагрузка с непредсказуемыми пиками** — функции масштабируются автоматически.

---

## 🏗️ Архитектура

```
[ Событие ] → [ Trigger ] → [ Function ] → [ Результат ]
     │                           │
     ▼                           ▼
[ API Gateway ]            [ Cloud Storage ]
[ БД (CDC) ]               [ Очередь ]
```

## 🔧 Реализация (пример на Go для AWS Lambda)

```go
package main

import (
    "context"
    "encoding/json"
    "github.com/aws/aws-lambda-go/lambda"
)

type OrderEvent struct {
    OrderID string `json:"order_id"`
    Status  string `json:"status"`
}

func HandleRequest(ctx context.Context, event OrderEvent) (string, error) {
    // Обработка события (например, обновление статуса заказа)
    return "Order " + event.OrderID + " processed", nil
}

func main() {
    lambda.Start(HandleRequest)
}
```

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Нет управления серверами | ❌ Ограниченное время выполнения (до 15 минут) |
| ✅ Автоматическое масштабирование | ❌ Холодный старт (cold start) |
| ✅ Оплата за фактическое использование | ❌ Сложно с долгими соединениями и состоянием |
| ✅ Упрощение развёртывания | ❌ Привязка к вендору (Vendor Lock-in) |
