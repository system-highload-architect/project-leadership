# Sharding (Шардирование)

**Sharding** — это метод горизонтального масштабирования данных, при котором данные распределяются по множеству узлов (шардов) на основе некоторого ключа (например, хеш-функции или диапазона значений). Каждый шард хранит только часть данных, что позволяет системе линейно масштабироваться при росте объёма данных и нагрузки.

Этот подход широко используется в распределённых базах данных (MongoDB, Cassandra, Citus для PostgreSQL), а также в кэшах и очередях.

---

## 🧠 Основные принципы

1. **Ключ шардирования (Shard Key).**  
   Поле, по которому данные распределяются по шардам (например, `customer_id`, `order_id`).

2. **Стратегия распределения.**  
   - **Range‑based:** данные распределяются по диапазонам значений (например, `id` от 1 до 1000 → шард 1, `id` от 1001 до 2000 → шард 2).
   - **Hash‑based:** ключ пропускается через хеш-функцию, и результат определяет шард (например, `hash(customer_id) % number_of_shards`).

3. **Маршрутизация запросов.**  
   Приложение или промежуточный слой (шардирующий прокси) определяет, в какой шард направить запрос на основе ключа шардирования.

4. **Перераспределение.**  
   При добавлении новых шардов данные должны быть перебалансированы (решаринг).

---

## 🧩 Когда использовать Sharding

- **Объём данных превышает возможности одного узла** (сотни гигабайт и более).
- **Нагрузка на запись/чтение слишком высока для одного узла.**
- **Требуется линейное масштабирование.**
- **Данные имеют естественный ключ для шардирования** (например, `user_id`).

---

## 🏗️ Архитектура

```
[ Приложение ]
       │
       ▼
[ Маршрутизатор (Shard Router) ]
       │
   ┌───┼───┐
   ▼   ▼   ▼
[Шард 1] [Шард 2] [Шард 3]
```

Каждый шард — это отдельный узел БД.

---

## 🔧 Пример реализации на Go (хеш-шардирование)

```go
type Shard struct {
    ID   int
    Data map[string]interface{}
}

type ShardManager struct {
    Shards []*Shard
}

func (sm *ShardManager) getShard(key string) *Shard {
    hash := 0
    for _, ch := range key {
        hash += int(ch)
    }
    idx := hash % len(sm.Shards)
    return sm.Shards[idx]
}

func (sm *ShardManager) Write(key string, value interface{}) {
    shard := sm.getShard(key)
    shard.Data[key] = value
}

func (sm *ShardManager) Read(key string) interface{} {
    shard := sm.getShard(key)
    return shard.Data[key]
}
```

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Линейное масштабирование | ❌ Сложность перебалансировки при добавлении шардов |
| ✅ Высокая производительность | ❌ Кросс-шардовые запросы сложны (JOIN, агрегации) |
| ✅ Отказоизоляция (падение одного шарда не влияет на другие) | ❌ Требуется правильный выбор ключа шардирования (иначе перекос) |
| ✅ Подходит для больших данных | ❌ Усложняет архитектуру приложения |
