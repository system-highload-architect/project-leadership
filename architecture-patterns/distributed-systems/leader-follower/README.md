# Leader-Follower

**Leader-Follower** — это паттерн координации в распределённых системах, при котором один узел (лидер) принимает все решения и управляет репликами (последователями). При отказе лидера выбирается новый.

Этот подход используется в системах с жёсткими требованиями к консистентности: базах данных (PostgreSQL, MongoDB), координаторах (ZooKeeper, etcd), кластерных очередях и распределённых блокировках.

---

## 🧠 Основные принципы

1. **Один лидер.**  
   Лидер принимает все запросы на запись и отвечает за координацию.

2. **Реплики (последователи).**  
   Синхронизируют состояние с лидером и могут обрабатывать запросы на чтение.

3. **Выборы лидера.**  
   При отказе лидера реплики проводят выборы нового лидера (алгоритм консенсуса).

4. **Согласованность.**  
   Обеспечивается через репликацию (синхронную или асинхронную).

---

## 🧩 Когда использовать Leader-Follower

- **Требуется строгая консистентность.**  
   Лидер гарантирует, что все записи выполняются в едином порядке.

- **Высокая доступность.**  
   При отказе лидера система продолжает работу после выборов.

- **Распределённые блокировки.**  
   Только лидер может выполнять критические операции.

---

## 🏗️ Архитектура

```
[ Лидер ] ← синхронизация → [ Последователь A ]
    │                            │
    └────────────────────────────┘
                 │
           [ Последователь B ]
```

Лидер принимает запросы, реплики синхронизируются с ним.

---

## 🔧 Пример реализации на Go (упрощённо)

```go
type Leader struct {
    ID      string
    Replicas []string
}

type Follower struct {
    ID     string
    Leader string
    Data   map[string]interface{}
}

func (l *Leader) Write(key string, value interface{}) error {
    // сохраняем у себя
    l.Data[key] = value
    // реплицируем на followers
    for _, r := range l.Replicas {
        r.replicate(key, value)
    }
    return nil
}
```

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Простота консистентности | ❌ Единая точка отказа (лидер) |
| ✅ Чёткая координация | ❌ Сложность выборов лидера |
| ✅ Простота отладки | ❌ Задержка при репликации |
