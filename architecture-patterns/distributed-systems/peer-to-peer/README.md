# Peer-to-Peer (P2P)

**Peer-to-Peer** (P2P) — это децентрализованная архитектура, в которой все узлы (пиры) равноправны и могут выступать как в роли клиента, так и в роли сервера. В отличие от клиент-серверной модели, здесь нет центрального координатора, и каждый узел может напрямую взаимодействовать с любым другим узлом в сети.

P2P широко используется в файлообменных сетях (BitTorrent), блокчейн-системах, децентрализованных базах данных и меш-сетях.

---

## 🧠 Основные принципы

1. **Децентрализация.**  
   Нет единой точки управления или отказа.

2. **Равноправие.**  
   Все узлы выполняют одинаковые функции и имеют одинаковый статус.

3. **Самоорганизация.**  
   Сеть динамически формируется: узлы подключаются и отключаются без центрального контроля.

4. **Маршрутизация.**  
   Сообщения доставляются через другие узлы (поиск пути в децентрализованной сети).

---

## 🧩 Когда использовать P2P

- Необходима высокая отказоустойчивость (нет единой точки отказа).
- Данные должны быть распределены и реплицированы между узлами.
- Система должна масштабироваться без центрального управления.
- Требуется поддержка автономности узлов.

---

## 🏗️ Архитектура

```
[ Узел A ] ↔ [ Узел B ] ↔ [ Узел C ]
    ↔ [ Узел D ] ↔ [ Узел E ]
```

Каждый узел хранит часть данных и может общаться с другими узлами через маршрутизацию.

---

## 🔧 Пример реализации на Go (простейший peer с HTTP)

```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
    // Открываем HTTP-сервер на порту 8080 для приёма сообщений
    http.HandleFunc("/data", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintf(w, "Peer data")
    })
    go http.ListenAndServe(":8080", nil)

    // Отправляем запрос к другому пиру
    resp, err := http.Get("http://localhost:8081/data")
    if err == nil {
        fmt.Printf("Ответ от другого пира: %v\n", resp.Body)
    }
}
```

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Отказоустойчивость | ❌ Сложность координации и согласованности |
| ✅ Масштабируемость | ❌ Сложность обнаружения узлов |
| ✅ Децентрализация | ❌ Сетевая нагрузка (поиск маршрутов) |
| ✅ Нет зависимости от одного узла | ❌ Безопасность сложнее |
