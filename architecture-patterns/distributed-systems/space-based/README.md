# Space-Based Architecture (Архитектура на основе пространства)

**Space-Based Architecture** (SBA) — это архитектурный стиль, который использует распределённую память (например, Hazelcast, Redis Cluster, Apache Ignite) как основное средство хранения и обмена данными между узлами. Все узлы имеют доступ к общему «пространству» данных, что позволяет им работать независимо и масштабироваться без единой точки отказа.

Этот подход особенно эффективен для систем с высокими требованиями к производительности, масштабируемости и отказоустойчивости, таких как:
- Системы реального времени.
- Высоконагруженные веб-приложения (сессии, кэши).
- Распределённые вычисления (in-memory processing).

---

## 🧠 Основные принципы

1. **Общее пространство данных.**  
   Все узлы имеют доступ к общему хранилищу в памяти, которое синхронизируется между ними.

2. **Отсутствие единой точки отказа.**  
   Данные реплицируются или шардируются по узлам, что обеспечивает отказоустойчивость.

3. **Масштабирование.**  
   При увеличении нагрузки добавляются новые узлы, которые автоматически включаются в кластер.

4. **Низкая задержка.**  
   Доступ к данным в памяти на несколько порядков быстрее, чем к диску.

---

## 🧩 Когда использовать Space-Based Architecture

- **Высокая нагрузка** — требуется обработка миллионов запросов в секунду.
- **Кэширование** — сессии пользователей, частые запросы к данным.
- **Распределённые вычисления** — обработка больших объёмов данных в реальном времени.
- **Отказоустойчивость** — данные не должны теряться при падении узла.

---

## 🏗️ Архитектура

```
[ Узел A ] ←→ [ Пространство данных (Hazelcast/Redis) ] ←→ [ Узел B ]
                    │                           │
                    ▼                           ▼
               [ Узел C ]                 [ Узел D ]
```

---

## 🔧 Инструменты

- **Hazelcast** — распределённая in-memory платформа (Java, .NET, C++).
- **Redis Cluster** — распределённый кэш с поддержкой кластеризации.
- **Apache Ignite** — распределённая in-memory БД с поддержкой SQL.
- **Memcached** — простой распределённый кэш.

## 🔧 Реализация на Go (пример с Redis Cluster)

```go
package main

import (
    "context"
    "fmt"
    "github.com/go-redis/redis/v8"
)

func main() {
    ctx := context.Background()

    rdb := redis.NewClusterClient(&redis.ClusterOptions{
        Addrs: []string{
            "redis-node1:6379",
            "redis-node2:6379",
            "redis-node3:6379",
        },
    })

    // Запись в пространство
    err := rdb.Set(ctx, "order:123", "active", 0).Err()
    if err != nil {
        panic(err)
    }

    // Чтение из пространства
    val, err := rdb.Get(ctx, "order:123").Result()
    if err != nil {
        panic(err)
    }
    fmt.Println("Order status:", val)
}
```

---

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Высокая производительность (in-memory) | ❌ Ограниченная ёмкость (память дороже диска) |
| ✅ Горизонтальное масштабирование | ❌ Eventual consistency (согласованность может быть не мгновенной) |
| ✅ Отказоустойчивость (репликация) | ❌ Сложность управления кластером |
| ✅ Низкая задержка | ❌ Не подходит для долговременного хранения |
