# Actor Model (Модель акторов)

**Actor Model** — это математическая модель параллельных вычислений, в которой основными единицами являются **акторы**. Каждый актор имеет:
- Входящую очередь сообщений (почтовый ящик).
- Поведение (как реагировать на сообщения).
- Состояние (может хранить данные).
- Возможность создавать другие акторы.

Акторы обмениваются сообщениями асинхронно, не имеют общего состояния и обрабатывают сообщения последовательно (одно за другим). Это делает их идеальными для построения отказоустойчивых, масштабируемых и конкурентных систем.

---

## 🧠 Основные принципы

1. **Изоляция.**  
   Акторы не имеют общего состояния и не разделяют память. Всё общение — через асинхронные сообщения.

2. **Последовательная обработка.**  
   Каждый актор обрабатывает сообщения по одному, в порядке поступления.

3. **Отказоустойчивость.**  
   Акторы могут наблюдать за другими акторами и перезапускать их при сбоях (иерархия акторов).

4. **Масштабируемость.**  
   Акторы могут быть распределены по узлам (кластерам) без изменения кода.

---

## 🧩 Когда использовать Actor Model

- Высокая конкурентность и параллелизм (тысячи/миллионы акторов).
- Распределённые системы, требующие отказоустойчивости.
- Системы реального времени (игры, телеком, финансовые транзакции).
- Системы с сложной обработкой событий и состояний.

---

## 🏗️ Архитектура

```
[ Актор A ] → сообщение → [ Актор B ]
      │                        │
      ▼                        ▼
 [ создаёт ]              [ создаёт ]
      │                        │
      ▼                        ▼
 [ Актор C ]              [ Актор D ]
```

Каждый актор имеет:
- **Почтовый ящик** — очередь входящих сообщений.
- **Поведение** — функция, обрабатывающая сообщения.
- **Состояние** — внутренние данные.
- **Дочерние акторы** — созданные им.

---

## 🔧 Инструменты

- **Akka** (Java/Scala) — самая популярная реализация.
- **Erlang/OTP** — язык, где акторы встроены на уровне платформы.
- **Proto.Actor** — реализация для Go, C#, Python.
- **Orleans** (Microsoft) — для .NET, с упором на распределённость.

## 🧩 Пример на Go (Proto.Actor)

```go
package main

import (
    "fmt"
    "github.com/asynkron/protoactor-go/actor"
)

// Сообщение
type Hello struct {
    Who string
}

// Актор
type HelloActor struct{}

func (state *HelloActor) Receive(ctx actor.Context) {
    switch msg := ctx.Message().(type) {
    case *Hello:
        fmt.Printf("Hello %s\n", msg.Who)
    }
}

func main() {
    // Создаём систему акторов
    system := actor.NewActorSystem()

    // Создаём актора
    props := actor.PropsFromProducer(func() actor.Actor { return &HelloActor{} })
    pid := system.Root.Spawn(props)

    // Отправляем сообщение
    system.Root.Send(pid, &Hello{Who: "World"})

    // Ждём завершения
    fmt.Scanln()
}
```

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Отказоустойчивость (супервизия) | ❌ Сложность отладки (асинхронность, распределённость) |
| ✅ Масштабируемость (миллионы акторов) | ❌ Не подходит для простых CRUD-приложений |
| ✅ Изоляция (нет общего состояния) | ❌ Требует специфического мышления (message-driven) |
| ✅ Естественная поддержка распределённых систем | ❌ Может быть избыточна для небольших проектов |
