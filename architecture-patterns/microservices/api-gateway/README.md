# Микросервисы с API Gateway

**API Gateway** — это единая точка входа для всех клиентов (веб, мобильные приложения, сторонние интеграции), которая маршрутизирует запросы к соответствующим микросервисам, выполняет агрегацию данных, аутентификацию, логирование, rate limiting и другие сквозные функции.

---

## 🧠 Основные принципы

1. **Единая точка входа.**  
   Все внешние запросы проходят через API Gateway, что упрощает управление доступом и мониторинг.

2. **Маршрутизация.**  
   Gateway направляет запросы к нужным сервисам на основе пути, метода или заголовков.

3. **Агрегация данных.**  
   Gateway может объединять ответы от нескольких сервисов в один ответ (например, заказ + информация о клиенте).

4. **Сквозная функциональность.**  
   Аутентификация, авторизация, rate limiting, кэширование, логирование, метрики.

5. **Трансформация протоколов.**  
   Gateway может принимать REST-запросы и преобразовывать их в gRPC для внутренних сервисов (и наоборот).

---

## 🧩 Когда использовать API Gateway

- У системы несколько типов клиентов (Web, Mobile, Third-party).
- Нужна централизованная аутентификация и авторизация.
- Требуется агрегация данных для уменьшения количества запросов с клиента.
- Нужно скрыть внутреннюю структуру микросервисов от внешнего мира.

---

## 🏗️ Архитектура

```
[ Клиент (Web/Mobile/API) ]
          │
          ▼
[ API Gateway ] ← маршрутизация, аутентификация, rate limiting, кэширование
          │
    ┌─────┼─────┐
    ▼     ▼     ▼
[Order] [Payment] [Inventory]
```

---

## 🔧 Реализация

**Инструменты:**
- **Envoy** / **KrakenD** — лёгкие, высокопроизводительные прокси.
- **Kong** / **Tyk** — полнофункциональные API-шлюзы.
- **Spring Cloud Gateway** / **Ocelot** — для Java/.NET.
- На старте можно использовать **самописный Gateway на Go** (с маршрутизацией через `http.ReverseProxy` и middleware).

**Пример на Go:**

```go
func main() {
    r := gin.Default()

    // Middleware: логирование, аутентификация, rate limiting
    r.Use(LoggerMiddleware())
    r.Use(AuthMiddleware())
    r.Use(RateLimiter())

    // Маршруты
    r.Any("/orders/*path", proxy("http://order-service:8080"))
    r.Any("/payments/*path", proxy("http://payment-service:8080"))

    r.Run(":8080")
}
```

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Единая точка входа, упрощение для клиентов | ❌ Единая точка отказа (нужна кластеризация) |
| ✅ Централизованная аутентификация и авторизация | ❌ Дополнительная задержка (один сетевой hop) |
| ✅ Упрощение клиентов (агрегация, трансформация) | ❌ Сложность отладки (дополнительный слой) |
| ✅ Лёгкость добавления сквозных функций | ❌ Требует тщательного проектирования маршрутов |
