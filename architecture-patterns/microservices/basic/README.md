# Базовые микросервисы

**Базовые микросервисы** — это минимальная реализация микросервисной архитектуры, где каждый сервис выполняет одну бизнес-функцию, имеет собственную базу данных и взаимодействует с другими через синхронные вызовы (REST/gRPC) или асинхронные события.

Этот подход является отправной точкой для перехода к микросервисам, когда команда только начинает осваивать распределённые системы.

---

## 🧠 Основные принципы

1. **Один сервис — одна бизнес-способность.**  
   Например, `Order Service`, `Payment Service`, `Inventory Service`.

2. **Каждый сервис владеет своими данными.**  
   У каждого сервиса своя база данных (или своя схема в общей БД).

3. **Коммуникация через API.**  
   Синхронная (REST/gRPC) и асинхронная (события, очереди).

4. **Независимые релизы.**  
   Сервисы можно обновлять независимо друг от друга (при соблюдении совместимости API).

5. **Автономность команд.**  
   Каждая команда отвечает за свой сервис (разработка, тестирование, деплой, поддержка).

---

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Чёткие границы ответственности | ❌ Распределённые транзакции (сложность) |
| ✅ Независимое масштабирование | ❌ Сетевая задержка (latency) |
| ✅ Возможность использовать разные технологии | ❌ Сложность мониторинга и отладки |
| ✅ Независимые релизы | ❌ Требует зрелой DevOps-культуры |

---

## 🏗️ Пример структуры базового микросервиса

```
order-service/
├── cmd/
│   └── server/
│       └── main.go
├── internal/
│   ├── domain/
│   ├── usecase/
│   ├── delivery/
│   └── repository/
├── pkg/
│   ├── logger/
│   └── config/
├── go.mod
└── Dockerfile
```

---

## 🔄 Взаимодействие между сервисами

- **Синхронное:** gRPC (предпочтительно) или REST для запросов, требующих немедленного ответа.
- **Асинхронное:** Kafka для событий (например, `OrderCreated` → `PaymentService` обрабатывает платеж).

---

## 🚀 Когда использовать

- Команда только начинает переход к микросервисам.
- Бизнес-способности чётко выделены и стабильны.
- Есть зрелый DevOps и инфраструктура для управления сервисами.
