# ADR-010: Выбор инструментов для диаграмм

**Статус:** Принято  
**Дата:** 2026-07-25  
**Автор:** Tech Lead

---

## Контекст

Для создания и поддержки архитектурных диаграмм (C4, UML, ER) необходим набор инструментов, который обеспечивает:

- Текстовое хранение диаграмм (версионирование, diff, code review).
- Возможность просмотра в браузере и в IDE.
- Генерацию изображений (SVG/PNG) для встраивания в документацию.
- Поддержку всех необходимых типов диаграмм (C4, UML, ER, последовательности, состояния, развёртывания).
- Низкий порог входа для команды.

Рассматривались:

1. **PlantUML** — текстовый язык для диаграмм.
2. **Mermaid** — встроенный в Markdown язык (поддерживается GitHub, GitLab).
3. **Draw.io / diagrams.net** — визуальный редактор с экспортом в XML/PNG.
4. **Structurizr** — специализированный инструмент для C4.
5. **StarUML** — классический инструмент для UML.

---

## Решение

Выбрана комбинация:

- **PlantUML** — основной инструмент для всех диаграмм (C4, UML, ER, последовательности, состояния, развёртывания).
- **Скрипты `generate-diagrams.sh`** для автоматической генерации SVG из `.puml` файлов.
- **Встраивание SVG** в Markdown-документацию (через `![диаграмма](path/to/diagram.svg)`).

**Обоснование:**

- **Текстовый формат:** Все диаграммы хранятся как код, что позволяет версионировать, ревьюить и автоматически генерировать.
- **Поддержка C4:** PlantUML имеет библиотеку C4-PlantUML, полностью покрывающую уровни Context → Code.
- **Широкий спектр диаграмм:** UML (классов, последовательностей, состояний, деятельности), ER, развёртывания, компонентов.
- **Интеграция с VS Code:** Плагин PlantUML позволяет просматривать диаграммы в реальном времени.
- **Генерация SVG:** Скрипты автоматически генерируют изображения для вставки в документацию.
- **Распространённость:** Большое сообщество, множество примеров, легко найти решение.

## Альтернативы

| Инструмент | Плюсы | Минусы | Почему не выбран |
|------------|-------|--------|------------------|
| **Mermaid** | Встроен в Markdown, поддержка GitHub/GitLab | Ограниченная поддержка C4 и сложных UML, менее выразительный | Недостаточно мощный для наших нужд |
| **Draw.io** | Визуальный редактор, интуитивно понятен | Бинарные или XML-файлы, сложнее версионировать и ревьюить | Неудобно для хранения в репозитории |
| **Structurizr** | Специализирован для C4, есть DSL | Платная версия, сложнее интеграция с UML | Избыточен, мы уже используем PlantUML |
| **StarUML** | Классический инструмент для UML | Не поддерживает C4, проприетарный формат | Не подходит для C4 и хранения в коде |

---

## Последствия

### Положительные
- ✅ Все диаграммы в текстовом формате, легко поддерживать.
- ✅ Автоматическая генерация SVG через `make generate-diagrams`.
- ✅ Единый стек для всех типов диаграмм.
- ✅ Интеграция с VS Code для локальной работы.

### Отрицательные
- ❌ Требуется установка Java и Graphviz для локального рендеринга.
- ❌ Синтаксис PlantUML требует обучения (но быстро осваивается).

### Компромиссы
- Используем **режим PlantUMLServer** для тех, у кого нет локальной Java.
- Храним сгенерированные SVG в репозитории рядом с `.puml` для просмотра в GitHub.
- В `README.md` добавляем инструкцию по установке и использованию.
