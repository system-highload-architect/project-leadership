# ADR-005: Выбор базы данных

**Статус:** Принято  
**Дата:** 2026-07-25  
**Автор:** Tech Lead

---

## Контекст
Для хранения данных Order Management System требуется надёжное и производительное хранилище. Основные требования:
- ACID-транзакции для поддержки целостности заказов.
- Возможность сложных запросов (JOIN, агрегации) для аналитики.
- Поддержка репликации и бэкапов.

Рассматривались реляционные (PostgreSQL, MySQL) и NoSQL (MongoDB) решения.

## Решение
Выбрана **PostgreSQL** как основная база данных.

**Обоснование:**
- Мощная поддержка SQL и JSON (JSONB) — гибкость для хранения метаданных заказов.
- Надёжность, репликация, Point-in-Time Recovery (PITR).
- Большое сообщество, инструменты миграции (golang-migrate).
- Лёгкая интеграция с событийной шиной через Debezium (CDC).

## Альтернативы
- **MongoDB**: отсутствие полноценных ACID-транзакций, сложнее с отчётами.
- **MySQL**: слабее в поддержке JSON, партиционировании, сложных запросах.

## Последствия
- ✅ Полноценные транзакции, надёжность.
- ❌ Вертикальное масштабирование — потребуется шардирование при росте.
- Мы внедряем кэширование (Redis) и проектируем схему с учётом будущего партиционирования.
